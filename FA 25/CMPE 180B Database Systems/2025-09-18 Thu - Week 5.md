# Lecture 08 – Complex Data Types

---

## 1. Overview
- Topic: Handling complex and non-traditional data in databases.
- Covers:
  - Semi-structured data (JSON, XML)
  - Object-oriented and hierarchical data
  - Querying complex data formats
  - Applications in modern systems and web services

---

## 2. Motivation for Complex Data
- Traditional relational databases assume simple, atomic values.
- Modern applications often require:
  - Storing **nested** or **hierarchical** data.
  - Supporting **frequent schema changes**.
  - Efficient **data exchange** between systems.
- Common in:
  - Web APIs
  - Configuration data
  - Scientific datasets
  - Enterprise integration

---

## 3. Semi-Structured Data
- Schema is flexible or implicit.
- Structure may vary across records.
- Example: JSON or XML documents.
- Useful for exchanging data between heterogeneous systems.

### Characteristics
- Data represented as trees or graphs.
- Missing or extra attributes are allowed.
- Attributes can have nested values or arrays.
- Enables easy evolution of schema.

---

## 4. Features of Semi-Structured Models

### 4.1 Flexible Schema
- **Wide column models:** each tuple can have different attributes.
- **Sparse representation:** fixed schema but many nulls allowed.

### 4.2 Multivalued and Nested Data
- Attributes can hold:
  - Sets (e.g., `{"La Liga", "Cooking", "Jazz"}`)
  - Maps (key-value pairs)
  - Arrays (ordered lists)

### 4.3 Map Operations
- `put(key, value)` – add or update a pair.
- `get(key)` – retrieve value.
- `delete(key)` – remove pair.

### 4.4 Array Data
- Efficient for sequential or scientific data.
- Example: `[5, 8, 9, 11]` instead of `{(1,5), (2,8), (3,9), (4,11)}`.

---

## 5. Non-First-Normal-Form (NFNF) Data
- Allows multi-valued or nested attributes directly in tuples.
- Supported in many modern databases (e.g., PostgreSQL JSONB, MongoDB).
- Simplifies modeling hierarchical information without excessive joins.

---

## 6. Nested Data Types: JSON and XML
- **JSON:** lightweight, text-based, modern format.
- **XML:** verbose but standardized and widely supported.

| Format | Characteristics | Typical Use |
|---------|----------------|--------------|
| JSON | Lightweight, human-readable, flexible schema | Web services, APIs |
| XML | Self-describing, validated by schemas | Enterprise data exchange |
