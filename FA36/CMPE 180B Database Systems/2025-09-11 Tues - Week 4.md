# Lecture 07 – File Organization and Indexing

## 1. Overview
- Focus: How data is physically organized and accessed on disk.
- Topics include:
  - File structures

  - Indexing and access paths
  - Hashing
  - B-trees and efficiency considerations

---

## 2. File Organization Concepts
- **File organization:** how records are stored physically in storage.
- **Goal:** minimize disk I/O and optimize access.
- **Common organizations:**
  1. **Heap (unordered):** records placed wherever space is available.
  2. **Sequential:** sorted by key.
  3. **Hash:** location determined by hash function.
  4. **Clustered:** multiple related records stored close together.

---

## 3. Record Storage Formats
- Records contain fields (attributes).
- Fixed-length records:
  - Each field has a fixed size.
  - Easy to compute record position.
- Variable-length records:
  - Used for text or mixed data types.
  - Use delimiters or offset tables to manage boundaries.

---

## 4. File Organization Types
### 4.1 Heap (Unordered) Files
- Records placed wherever space exists.
- New insertions appended or placed in free space.
- **Pros:** simple and efficient for bulk inserts.
- **Cons:** poor for searching unless an index is used.

### 4.2 Sequential Files
- Records kept in sorted order by search key.
- **Pros:** efficient for range queries and sequential scans.
- **Cons:** costly for insertions and deletions (must maintain order).

### 4.3 Hash-Based Organization
- Hash function maps key → bucket address.
- **Pros:** fast equality searches.
- **Cons:** poor for range queries or non-uniform distributions.

---

## 5. Indexing Overview
- **Index:** data structure that speeds up record retrieval.
- Each entry = (search-key value, pointer to record).
- Analogy: index of a book.
- **Goal:** reduce number of disk accesses for queries.

---

## 6. Types of Indices
| Type | Description | Example Use |
|-------|--------------|-------------|
| **Primary (Clustering) Index** | Search key determines physical order of records | Index on primary key |
| **Secondary (Non-clustering) Index** | Search key is different from sort order of file | Index on salary field |
| **Dense Index** | Every search-key value has an index entry | Small tables or frequently accessed fields |
| **Sparse Index** | Only some key values have entries | Large sorted datasets (saves space) |

---

## 7. Dense vs Sparse Indices
### Dense Index
- Every key value appears in the index.
- Provides direct access to every record.
- Requires more space and maintenance.

### Sparse Index
- Contains entries only for some records.
- Used with sequentially ordered files.
- Find nearest smaller key in index, then scan forward.
- Less space and update cost.

---

## 8. Multilevel Indexing
- When an index is too large for memory:
  - Create a second-level index (sparse index on first index).
- **Inner index:** main index file.
- **Outer index:** index over the inner index.
- Additional levels can be added recursively.
- Improves lookup speed with minimal storage overhead.

---

## 9. Indices on Multiple Keys
- **Composite key index:** built on multiple attributes.
- Example: `(name, ID)`
- Sorted lexicographically:
  - (John, 12121) < (John, 13514) < (Peter, 11223)
- Allows queries on combinations or individual components.

---

## 10. Indexed Sequential Access Method (ISAM)
- Classic indexing method developed by IBM.
- Combines sequential file organization with an index.
- Allows both sequential and direct (random) access.
- Used in mainframes and legacy systems.
- Modern systems replaced ISAM with **B+ trees** for dynamic updates.

---

## 11. B+-Tree Index
### Structure
- Balanced tree structure.
- All leaves are at the same depth.
- Internal nodes form a hierarchy of sparse indices.
- Nodes contain key-pointer pairs.

### Properties
- Non-leaf nodes: between ⌈n/2⌉ and n children.
- Leaf nodes: between ⌈(n–1)/2⌉ and n–1 key values.
- Root node:
  - At least 2 children if not a leaf.
  - If it’s a leaf, can hold 0 to n–1 keys.

---

## 12. B+-Tree Example (n = 6)
- Leaf nodes hold between 3 and 5 key values.
- Internal nodes hold between 3 and 6 child pointers.
- Root must have at least 2 children.
- Search operations require traversing from root to leaf.

---

## 13. B+-Tree Node Components
- **Keys (K):** sorted values.
- **Pointers (P):**
  - To child nodes (non-leaf nodes).
  - To records or record buckets (leaf nodes).
- Example: `[K1, K2, ..., Kn-1]` with pointers `[P1, P2, ..., Pn]`.
